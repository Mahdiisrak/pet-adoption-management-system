6. Final startup instructions

This reset removes only the project’s Docker Oracle volume. It is appropriate because it contains only freshly created demo data.
cd /d E:\pet-adoption-system
docker compose down -v
docker compose up --build --force-recreate

After first-time Oracle initialization finishes, open http://localhost:8081.

Demo login: admin / password

For external database tools, use localhost:1522/XEPDB1, user PET_ADMIN, and the password configured in .env.

7. Database connection and adding data

The project is connected to Oracle automatically. The backend container uses database:1521/XEPDB1; database is the Docker Compose service name. The frontend calls the backend through Nginx, so all three services are connected.

Use SQL Developer (recommended): create a new Oracle connection with Host localhost, Port 1522, Service name XEPDB1, Username PET_ADMIN, and the value of APP_USER_PASSWORD in the root .env file.

Use the terminal: replace YOUR_APP_USER_PASSWORD with the value in .env.

cd /d E:\pet-adoption-system
docker compose exec database sqlplus PET_ADMIN/YOUR_APP_USER_PASSWORD@//localhost:1521/XEPDB1

Inside SQL*Plus or SQL Developer, add data with an INSERT, then persist it with COMMIT. Example:

INSERT INTO PERSON (PERSON_ID, FIRST_NAME, LAST_NAME, DATE_OF_BIRTH, GENDER, EMAIL)
VALUES ('P021', 'Amina', 'Rahman', DATE '1998-06-15', 'FEMALE', 'amina@example.com');

COMMIT;

SELECT PERSON_ID, FIRST_NAME, LAST_NAME, EMAIL
FROM PERSON
WHERE PERSON_ID = 'P021';

Use a new, unique primary key and respect foreign-key relationships: insert parent rows (for example, PERSON) before dependent rows (for example, PERSON_PHONE). Changes stored in the Docker volume remain after docker compose down; they are erased only by docker compose down -v.
